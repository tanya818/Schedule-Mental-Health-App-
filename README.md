# Mental Health App API

FastAPI service backed by PostgreSQL, used by the React Native mobile app.

Users sign in with **Google**. The app gets a Google ID token from the Google SDK,
sends it to `POST /auth/google`, and gets back an access token for this API.
Every other endpoint needs `Authorization: Bearer <access_token>`.

| Method | Path | Auth | Purpose |
|---|---|---|---|
| `POST` | `/auth/google` | none | Sign in with a Google ID token. Creates the user on first sign-in. |
| `POST` | `/auth/dev-login` | none | **Development only** (`ENV=development`). Sign in as any email, no Google. |
| `POST` | `/auth/logout-all` | Bearer | Invalidate all of this user's access tokens (all devices). |
| `GET` | `/users/me` | Bearer | Read the logged-in user |
| `PUT` | `/users/me` | Bearer | Update name / age / gender (onboarding + profile edits) |
| `POST` | `/users/me/events` | Bearer | Create an event on the logged-in user's schedule |
| `GET` | `/health` | none | Health check |

Tables: `users`, `events` (see `app/models.py`). `events.user_id` is a foreign
key to `users.id` (one user → many events, `ON DELETE CASCADE`).

## Sign-in flow

1. The app signs in with Google (Google SDK) and receives a Google **ID token**.
2. App → `POST /auth/google {"id_token": "..."}`.
3. The API verifies the token (Google signature, audience = `GOOGLE_WEB_CLIENT_ID`,
   expiry, verified email), then finds the user by Google `sub`, links an existing
   user by email, or creates a new one.
4. The API returns `access_token` (valid `ACCESS_TOKEN_MINUTES`, default 60),
   `is_new_user` and `user`. If `is_new_user` is true, the app shows onboarding
   and calls `PUT /users/me`.
5. The app sends `Authorization: Bearer <access_token>` on every request.
   On `401`, it does a silent Google sign-in and calls `/auth/google` again.

## Notes / assumptions made while building this

- **IDs are UUIDs**, generated by Postgres (`uuid_generate_v4()`), matching the
  `users` table DDL you provided — not the `int` shown in the original API
  sketch. `app/database.py` enables the `uuid-ossp` extension automatically
  on startup so `uuid_generate_v4()` works.
- **Users are created by `POST /auth/google`**, not by a signup endpoint.
  `email` comes from Google and can't be changed with `PUT /users/me`.
- **Users are identified by Google's `sub`** (`users.google_sub`), not by email,
  because a Google account's email can change. Users created before Google
  sign-in are linked by email the first time they sign in.
- **`category` on events is a placeholder enum** (`work`, `personal`,
  `health`, `social`, `sleep`, `other`) in `app/schemas.py` — swap in your
  real category list whenever you have it; it's a one-line change.
- **`email` is unique** at the database level.
- **Recurring events** use a `recurrence` object instead of a true/false flag:
  `frequency` (`daily` | `weekly` | `monthly` | `yearly`), `interval` (every N
  periods, default 1), `days_of_week` (weekly only, e.g. `["mon","wed"]`;
  defaults to the start day) and `until` (last date, optional). Omit
  `recurrence` for a one-time event. One row is stored per event; individual
  occurrences will be calculated when events are read.
- **Event validation**: `end_time` must be after `start_time`, or the API
  returns `422`.

## Setup

1. Create a virtual environment and install dependencies:
   ```
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. Make sure Postgres is running and the `mentalhealth` database exists:
   ```
   brew services start postgresql@16
   createdb mentalhealth
   ```

3. Copy `.env.example` to `.env` and fill it in:
   ```
   cp .env.example .env
   ```
   - `GOOGLE_WEB_CLIENT_ID`: your **Web** OAuth client ID from Google Cloud Console
   - `JWT_SECRET`: run `openssl rand -hex 32` and paste the result
   - `ENV=development` enables `/auth/dev-login` for local testing

   **Existing database?** Starting the app doesn't change existing tables, so run
   any migrations you haven't run yet, in order (a fresh database doesn't need them):
   ```
   psql mentalhealth -f migrations/001_google_signin.sql    # Google sign-in columns on users
   psql mentalhealth -f migrations/002_event_recurrence.sql # recurring -> recurrence rule on events
   ```

4. Run the API:
   ```
   uvicorn app.main:app --reload
   ```
   On startup this enables the `uuid-ossp` extension and creates the `users`
   and `events` tables if they don't exist yet.

5. Open the interactive docs at http://127.0.0.1:8000/docs

## Example requests

Sign in (development shortcut) and save the token:
```
TOKEN=$(curl -s -X POST http://127.0.0.1:8000/auth/dev-login \
  -H "Content-Type: application/json" \
  -d '{"email": "jane@example.com", "name": "Jane Doe"}' | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")
```

Read the logged-in user:
```
curl http://127.0.0.1:8000/users/me -H "Authorization: Bearer $TOKEN"
```

Update the profile (onboarding):
```
curl -X PUT http://127.0.0.1:8000/users/me \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Jane Doe", "age": 29, "gender": "female"}'
```

Create an event:
```
curl -X POST http://127.0.0.1:8000/users/me/events \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
        "name": "Team standup",
        "start_time": "2026-10-01T09:00:00Z",
        "end_time": "2026-10-01T09:30:00Z",
        "stress_level": 3,
        "category": "work",
        "description": "Weekly sync",
        "recurrence": {
          "frequency": "weekly",
          "interval": 1,
          "days_of_week": ["mon", "wed"],
          "until": "2026-12-31"
        }
      }'
```

## Testing with Postman

**Quick way (no Google):** `POST http://127.0.0.1:8000/auth/dev-login`
```json
{ "email": "test@example.com", "name": "Test User" }
```

**Real Google sign-in:** get a Google ID token with Postman's OAuth 2.0 tab
(Auth URL `https://accounts.google.com/o/oauth2/v2/auth`, Token URL
`https://oauth2.googleapis.com/token`, your Web client ID/secret, scope
`openid email profile`, "Authorize using browser"), copy the `id_token`, then:
`POST http://127.0.0.1:8000/auth/google`
```json
{ "id_token": "eyJ..." }
```

Copy `access_token` from the response and use it as a **Bearer Token** for
`GET /users/me`, `PUT /users/me` and `POST /users/me/events`.
