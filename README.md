# Mental Health App API

FastAPI service backed by PostgreSQL. Currently implements:

- `GET /users/{user_id}` — read a user's info
- `POST /users` — create a new user
- `PUT /users/{userId}` — full update of a user
- `POST /users/{userId}/events` — create a new event on a user's schedule

Tables: `users`, `events` (see `app/models.py`). `events.user_id` is a foreign
key to `users.id` (one user → many events, `ON DELETE CASCADE`).

## Notes / assumptions made while building this

- **IDs are UUIDs**, generated by Postgres (`uuid_generate_v4()`), matching the
  `users` table DDL you provided — not the `int` shown in the original API
  sketch. `app/database.py` enables the `uuid-ossp` extension automatically
  on startup so `uuid_generate_v4()` works.
- **`POST /users` and `PUT /users/{userId}` don't accept `id` or `createdAt`**
  in the request body — those are generated by the database. Sending them
  would be redundant/unsafe (a client could otherwise pick its own ID or
  fake a creation date).
- **`category` on events is a placeholder enum** (`work`, `personal`,
  `health`, `social`, `sleep`, `other`) in `app/schemas.py` — swap in your
  real category list whenever you have it; it's a one-line change.
- **`email` is validated as a real email address** (via Pydantic's
  `EmailStr`) and is enforced unique at the database level — `POST /users`
  and `PUT /users/{userId}` return `409 Conflict` if the email is taken.
- **Event validation**: `end_time` must be after `start_time`, or the API
  returns `422`.

## Setup

1. Create a virtual environment and install dependencies:
   ```
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. Make sure Postgres is running and the `mentalhealth` database exists:
   ```
   brew services start postgresql@16
   createdb mentalhealth
   ```

3. Copy `.env.example` to `.env` and set your `DATABASE_URL` (replace
   `YOUR_MAC_USERNAME` — run `whoami` to check):
   ```
   cp .env.example .env
   ```

4. Run the API:
   ```
   uvicorn app.main:app --reload
   ```
   On startup this enables the `uuid-ossp` extension and creates the `users`
   and `events` tables if they don't exist yet.

5. Open the interactive docs at http://127.0.0.1:8000/docs

## Example requests

Create a user:
```
curl -X POST http://127.0.0.1:8000/users \
  -H "Content-Type: application/json" \
  -d '{
        "name": "Michael",
        "email": "michael@example.com",
        "age": 30,
        "gender": "male"
      }'
```
Copy the `id` from the response, then:

Read the user:
```
curl http://127.0.0.1:8000/users/PASTE_USER_ID
```

Update the user:
```
curl -X PUT http://127.0.0.1:8000/users/PASTE_USER_ID \
  -H "Content-Type: application/json" \
  -d '{
        "name": "Michael S",
        "email": "michael@example.com",
        "age": 31,
        "gender": "male"
      }'
```

Create an event for that user:
```
curl -X POST http://127.0.0.1:8000/users/PASTE_USER_ID/events \
  -H "Content-Type: application/json" \
  -d '{
        "name": "Team sync",
        "start_time": "2026-09-15T15:00:00Z",
        "end_time": "2026-09-15T16:00:00Z",
        "stress_level": 5,
        "recurring": true,
        "category": "work",
        "description": "Weekly sync"
      }'
```
